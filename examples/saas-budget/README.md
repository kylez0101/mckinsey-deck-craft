# 客服投入决策：证据不足时怎样提出有限建议

简报：董事会需要决定是否从30万元预算中批准一个90天的知识库试点。工单合成记录从1月10,000件上升至3月15,000件，但根因、效果和回收期都未知。三个候选的90天支出估算分别为22万元、15万元、28万元；后续持续成本另行评审。口径及状态登记在 `source.json` 的来源台账。

这套报告把“出现了值得调查的问题”和“已经证明某种方案有效”分开。推荐知识库的依据是一个需要确认的试点选择，效果必须通过基线与小范围验证取得；它不是由最低成本或虚构ROI推导出的最优解。准入条件与预算不满足时，标题和最终建议都改为暂缓。

## 教学改写对照

下列“修改前”是为说明问题自拟的写法，没有运行过的模型基线之意。

| 修改前 | 本例处理 | 判断依据 |
|---|---|---|
| “知识库将显著提高效率，快速收回投资” | “建议开展有条件的知识库试点” | 输入没有效果或回收期证据，保留验证条件 |
| 标题“客服现状”，并列工单、满意度和预算三个大数字 | 用单一趋势页解释工单增加，根因另列待验证 | 当前页只证明工作量变化，避免指标并置暗示因果 |
| 三种方案各占一张装饰卡片 | 同一开放表格比较支出、机制与效果状态 | 统一比较维度，未知值可直接对照 |
| 末页只列22万元总额 | 展开16万软件、4万内容、2万核对，旁列授权条件 | 金额闭合，读者可以检查费用与拨款权限 |

页面留白用于区分主证据、解释与决策请求。来源不是用来补救主张过强的脚注；影响是否实施的条件保留在屏幕上，完整状态与来源ID进入备注。
