# 共享研究服务：把需求、可执行性与治理分开

简报：两院系讨论首学期共享研究支持服务。合成台账有30件单月请求，分别是资料检索12件、数据整理10件、方法咨询8件。预算上限10万元，可用人员2人；共享试点最低需要2人，估算支出9万元。输入假设院系已确认治理范围，但正式项目仍需核实。服务效果尚未测量。

本例选择试行共享服务，依据是建议的服务优先级、预算与人员条件共同成立。30件请求只说明分类数量，不等于工时需求或项目价值；保留院系审批权是建议设计边界，不假装为既有校级政策。

## 教学改写对照

以下“修改前”为自拟教学反例，不代表真实模型测试结果。

| 修改前 | 本例处理 | 判断依据 |
|---|---|---|
| “建立先进研究中心，全面赋能科研” | “建议在两院系试行共享研究服务” | 明确服务对象、范围与决定；没有全校规模化的证据 |
| 用30件请求推算收益或编制 | 展示请求分类，先补处理工时与权限记录 | 请求数量不能直接证明人员需求或价值 |
| 以三步时间线表示人员、预算、治理条件 | 三项并列条件通过AND门槛后，再画实际工作流 | 准入条件要同时成立，不能误画成依次完成的业务步骤 |
| 用无条件的绿色推荐行强调共享方案 | 比较表保持中性，建议随可执行性重新生成 | 预算或人员改变后，颜色不能留下错误推荐 |

前半套解释需求及选择，后半套说明启动条件与复核方式。阶段表和流程图都用原生对象；原生可编辑不代表在PowerPoint手改人数后正文会自动更新。持续改数应修改统一源文件并重新生成。
