# 六种数据分析布局

这些布局补充 T01–T10。封面、页标题、来源、备注由主构建器生成；数据页只承担证据表达。业务数据必须先经过 `data-model.mjs` 解析和计算，不能在页面模块中补数。

| 布局 | 适用问题 | 页面结构 | 容量 |
| --- | --- | --- | --- |
| A01 比较主图 | 哪项更高、差多少 | 横向原生条形图占满正文宽度，结论在底部 | 2–7 类别、1–2 系列 |
| A02 比较与解释 | 差异如何影响选择 | 左侧主图，右侧开放式解释栏 | 同 A01；1–3 条解释 |
| A03 趋势主图 | 随时间发生什么变化 | 横向完整时间轴与原生折线图 | 3–8 时点、1–2 系列 |
| A04 趋势与解释 | 转折、差距意味着什么 | 左侧趋势图，右侧解释栏 | 同 A03；1–3 条解释 |
| A05 决策总表 | 多个方案在哪些条件上不同 | 全宽开放式原生表格 | 2–5 行方案、2–6 列 |
| A06 决策与条件 | 为什么选它、何时可以执行 | 左侧紧凑表格，右侧决策条件栏 | 2–4 行方案、2–5 列；1–3 条解释 |

这些是结构变体，不只是颜色变化：A01/A03 把空间让给证据；A02/A04 将解释放在独立的纵向阅读带；A05 提供完整横向比较；A06 让条件和决策与紧凑证据并读。不要用开放解释栏装下与图表无关的通用口号。

## 数据字段

所有布局继承主构建器字段 `layout,title,subtitle,source,notes`。

图表布局的专属字段：

```json
{
  "chart": {
    "categories": ["甲", "乙", "丙"],
    "series": [{"name": "基准", "values": [0, 12, 18]}],
    "unit": "单位：万元／季度",
    "format": "#,##0.0",
    "min": 0,
    "emphasisIndex": 2,
    "emphasisReason": "丙方案保留最高的基准贡献"
  },
  "caption": "估算不含一次性迁移费用",
  "takeaway": "结论需由输入数据和条件共同支持"
}
```

- `unit` 必填，写完整单位和时间口径；数值与其一致。`format` 是原生 PowerPoint 数字格式，如 `0.0%`；此时 31% 应存为 `0.31`。
- `min,max` 可选。条形图始终包含零；非负比较不能截断为正的最小值。负数条形图必须显式给出包含所有值与零的 `min`。不允许隐藏数值或压缩轴来放大差异。
- `emphasisIndex` 从零开始，必须同时给出 `emphasisReason`。单系列比较仅为该类别着主色；未指定时全组采用同一主色，不会默认把最后一项当赢家。双系列默认以主色与中性色区分；用户显式指定accent时，参照系列可使用该辅助色，不给各类别分配多种颜色。
- `categories` 保留源顺序。趋势必须由作者提供按时间递增的类别；常见年月、季度及“第 n 周”等标签会检查顺序。不会自动按数值排序或假设字符串排序就是时间顺序。
- 单系列趋势保留点值；双系列趋势使用不同点型、系列图例及首末数值，减少中段标签碰撞。折线不平滑，不补插值，不连接未知值。
- 自动轴的端点按同一自然步长对齐，使混合正负值的零点能够落在刻度上；显式输入的 `min,max` 保留原值。负数的趋势标签放在点上方，避免与底部时间类别相贴。
- 图表仅接受完整有限数。`null`、缺失和未知值会报错，不能填零后继续绘制。未知值应显式标在表格中，或换用支持缺口的表达方式。
- `caption` 可选；没有 caption 时，比较中的强调理由可作为图下说明。`takeaway` 可选，必须由数据支持。

A02/A04/A06 另需：

```json
"insights": [
  {"heading": "选择依据", "text": "具体证据与对决策的影响"},
  {"heading": "执行条件", "text": "预算、门槛或需要验证的条件"}
]
```

解释栏最多三条，每条标题一行、正文三行。正文约每 13 个中文单位插入安全换行，最多利用一个单位的标点余量；完整数字、英文 token 及跟随数字的常见单位一起保留，所有原始字符都保留。超过三行或存在无法放入一行的连续 token 时应改写显示格式、改用主图布局或另起一页，不能压小字号或裁切。

表格布局的专属字段：

```json
{
  "headers": ["方案", "投入／万元", "净贡献／万元", "执行条件"],
  "rows": [["甲", "0", "0", "维持现状"], ["乙", "12.0", "8.4", "预算通过后试点"]],
  "numericColumns": [1, 2],
  "highlightRow": 1,
  "columnWidths": [224, 190, 210, 540],
  "takeaway": "选择和条件需与测算结果保持一致"
}
```

- `rows` 保留全部字段，不允许缺列、`null` 或未定义值；未知值以明确文本表示，零必须显示为零。
- `numericColumns` 是从零开始的列号，标题和数值都右对齐。数值的精度、正负号和千位格式由数据编译阶段生成，表格不重新计算或擅自取绝对值。
- `highlightRow` 是从零开始的正文行号，选中行使用浅色底与窄色线，不能用着色暗示未经定义的评分或推荐。
- `columnWidths` 可选。A05 总和为 1164 px，A06 总和为 806 px；每列至少 96 px。默认第一列约占四分之一，其余平均分配。长条件列应明确分配更宽空间，或减少同页列数。
- 开放规则线、浅色选中行和对齐承担层级。不要为每个单元格增加边框、为每列分配颜色或加入没有依据的评分。
- A05 正文单元格最多两行，A06 最多三行。表头最多两行。容量守卫失败时会报告字段位置，不会截断或缩小字体。

## 主题与复用接口

`scripts/data-pages.mjs` 导出 `allowedDataPageFields` 与同步函数 `renderDataPage({slide,p,theme,helpers})`。

- `theme` 必须是 `createTheme()` 的返回值；页面从 `theme.C` 读取颜色。模块不包含固定蓝色、逐项彩虹色或新的颜色推导。
- `helpers` 提供 `tx,rule,shape,nativeTable,takeaway,applyPresentationChartFont`。前五项使用原构建器签名；最后一项使用当前 Presentations runtime 的函数，调用形如 `applyPresentationChartFont(chart,{fontFamily:'Arial Unicode MS'})`。
- 返回 `{hasChart,hasTable}`，主构建器将相应页加入原生图表／表格所有者列表并执行最终校验。当前六款布局不自行推断合计，算术关系应由源数据模型统一声明和验证。
- 所有图形、文字及表格仍为原生对象。重新生成会更新原生点值与标签；直接在 PowerPoint 中手动更改数据，不会自动改写正文解释、推荐或表格合计。

每次改变结构或字体，必须检查实际渲染与 PowerPoint 目标应用。通过容量检查只表示没有超出已知输入限制，不等于页面已经完成视觉验收。

[完整可编辑布局库](../assets/templates/data-layout-library.pptx)与[统一源文件](../assets/templates/data-layout-source.json)展示同一批证据的六种结构。示例主色为深青，用户可通过theme.primary覆盖正文主题，固定封面独立保留。

双行表头会增加行高，正文也按实际行数增加留白。五行容量指短内容；多行证据使总高度超过页内可用范围时，构建器会要求拆页或换更宽布局。推荐行的背景与左强调条都使用同一组实际行高计算，避免单位碰线与强调错位。未显式指定数字格式时，整数使用无小数格式，分数使用两位小数；有特殊精度时由作者明确设置。
