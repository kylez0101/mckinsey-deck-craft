# 内容、视觉与交付质量

这些是个人Skill的检查规则，不是原机构内部审稿制度。结论给具体页码与证据，不能只给总分；内部检查通过不替代用户对实际效果的反馈。

## 必须解决的失败条件

- 发明来源、数字，或把目标、测算、潜在价值和示意写成已实现结果。
- 正文不支持标题，缩写误读，单位、周期、基准或分母不一致。
- 总览与展开的名称/编号无说明变化；残留旧主题、目录、脚注或占位。
- 原图缺失、表格截断、文字溢出、关键条件或连线无法阅读。
- 要求可编辑PPT，却交整页截图/PDF而未说明限制。
- 完整报告缺少本用户要求的固定深蓝原图白字封面，或使用已替换的旧封面。

这些问题未解决时不称定稿。真实缺失数据可以明确未知、用有标示的假设或提供补证计划，不能补造。

## 四类证据

| 标准 | 检查动作 |
|---|---|
| 整篇逻辑 | 只读标题，再沿问题、证据、机制和行动回读；每页有职责，转折有支撑 |
| 事实与计算 | 逐项核对来源、口径、假设、单位、分母和结果状态，区分相关与因果 |
| 视觉解释 | 看图能复述比较、流程、结构或取舍；层级、密度、节奏和图例/轴完整，标题尽量单行 |
| 可用交付 | 最终文件范围正确，实际渲染可读，代表对象可修改、重开；工作簿与显示数据一致 |

结构校验、全尺寸视觉、实际修改重开以及目标应用检查分别记录，不能互相代替。验收对象是最终导出文件；目标应用不可用时明确范围。动作权限和关键限制保留在屏幕，细则进入真实备注。

## 专项核对

- 多方案先定义集合与分母；相对日期首次出现时定义基准事件。人日/产能结合实际工时与前置条件，不靠延长日历工期掩盖资源不足。
- 图表说明相较清单增加了什么判断。真实XY尺度、情景非置信区间、归一比例的各自分母、父子金额不重复累计，见[图表规则](professional-chart-design.md)。
- 查看原点标签与刻度、相邻点、表头/末行留白、子项缩进、容器反白文字，以及推荐背景和强调条对齐。
- 改数直接核对最终缓存、真实工作簿、表格、标签、正文、标题与备注，不只看解析JSON。推荐和强调理由由当前条件支持；未知值不变成零。
- 输入变化若触发最低人数、批次、台班或预算限制，先重新判断可执行组合。阈值保留对象、指标、时间、分母与触发动作。
- 检查主色、辅助色实际落在对应对象；小字与图形边界分别满足可读目标，不能只看主题算法结果。

## 迁移与盲测

选择未用于归纳的新主题，冻结简报和Skill。执行者只取得Skill、原始事实和必要运行环境，不提前给预期答案、页序、已知问题或修复方法。另一评估者独立检查完整产物与简报：有没有硬套制造框架、资料不足是否保留状态、标题与图形是否适合页面职责、行动是否有责任和检验条件。

故事板只证明叙事迁移，不能替代完整PPT的渲染与编辑验收。分别记录编译失败、完整构建、自检修复、首轮独立审查及反馈后的回归，不把修复重放当新盲测。合成案例不证明真实经营效果，也不证明所有行业、篇幅和字体环境已覆盖。测试过程与版本保存在项目目录，现行交付动作见[成品检查](production-checks.md)。
